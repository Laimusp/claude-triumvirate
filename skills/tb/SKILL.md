# ТБ — Триумвират Богов

> ⚠️ **Дефолт ТБ = ДВА бога (Codex + АГ), БЕЗ ЧК. ЧК — резервный третий бог: подключать ТОЛЬКО когда юзер явно сказал «с чк» / «полный ТБ» / «чк-макс» или дал разовый прямой приказ. Без этих слов ЧК НЕ запускать (и НЕ использовать как авто-замену упавшего бога). «Все трое/три ответа» ниже читать как «все боги текущего прогона: по умолчанию два, с ЧК — три».**

Независимые боги ревьюят **один и тот же артефакт**. Основной процесс — **арбитр**. Всё.

Анти-author-bias: автор кода защищает свой код («я так задумал»), поэтому ревьюят внешние боги, а основной процесс не оценивает код до сбора их ответов.

## Принцип: боги атомарны и одинаковы

Каждый бог = функция: **вход `{артефакт + что-код-должен-делать + формат}` → выход `{findings}`**.
Все три получают ОДНО И ТО ЖЕ. Различается только движок. Никаких особых правил под конкретного бога.

## Боги (по умолчанию Codex + АГ; ЧК — резерв по слову юзера)

1. **Codex** — `mcp__codex__codex`, single-shot, без `model` (сток из `~/.codex/config.toml` — его же читает `codex mcp-server`), `approval-policy: "never"`, `sandbox: "danger-full-access"`.
2. **Gemini-плечо (второе мнение) = Antigravity АГЕНТ** — `mcp__antigravity__ask-antigravity` (MCP-сервер: github.com/Laimusp/antigravity-mcp). Реагирует на ЛЮБОЕ слово юзера: «Гемини», «АГ», «Антигравити», «Antigravity» — все ведут сюда. Это **настоящий agy CLI-агент с тулами** (Read/Write/Bash, как Codex/ЧК), ПО УМОЛЧАНИЮ видит проект (cwd), а НЕ голый API. Даём `prompt_file` = **абсолютный** путь к `.tb-artifact.md`, системку (божественный промпт + read-only) — в параметр `system`. **read-only — инструкцией капсом** (как у Codex): agy-агент по умолчанию видит проект (нода отдаёт `process.cwd()` в `--add-dir`), технического барьера на запись НЕТ — поэтому read-only держится read-only-блоком в `system`. `workspace` можно не трогать (или передать `"none"` для temp-изоляции; артефакт он и так читает по `prompt_file`). **НЕ ставить `cleanup`** — артефакт общий для всех богов, удаляет его ТБ в конце цикла. Модель форсится в **Pro High** через env `AGY_MODEL=gemini-pro-agent` (в `.claude.json` → mcpServers.antigravity.env). ⚠️ БЕЗ этого env MCP-агент стартует в чистом изолированном профиле `~/.agy-mcp-profile` (без своего `antigravity-cli/settings.json`) и `agy` по умолчанию берёт **Flash**, а НЕ Pro — поэтому env обязателен, иначе бог №2 тихо ревьюит на слабой модели. Ротация аккаунтов по квоте — внутри backend, на стороне ТБ ничего не делаем.
3. **[РЕЗЕРВ — запускать ТОЛЬКО по явному слову юзера «с чк» / «полный ТБ» / «чк-макс»] Чистый Claude (кратко «ЧК»)** — отдельный процесс через `Bash(run_in_background=true)`. Дефолт `--effort high`; если юзер сказал **«чк-макс» / «чкмакс» / «ЧК макс»** → поднять до `--effort max` на этот прогон:
   ```
   claude -p 'Прочитай файл <путь-к-артефакту> и выдай findings по формату из файла. Только анализ.' \
     --model claude-opus-4-8 --effort high \
     --disallowedTools "Edit Write NotebookEdit" \
     --append-system-prompt '<системка>' --output-format json
   ```
   Результат — в `.result` (harness пишет stdout в файл, читать его).

Codex + Gemini-плечо — в одном tool-use блоке, параллельно; ЧК (если позван юзером) — в том же блоке через `Bash(run_in_background=true)`. **Все — настоящие агенты с Read, все получают ПУТЬ к артефакт-файлу** (единообразно): Codex читает его сам; Antigravity — через `prompt_file` (MCP запускает agy-агента, который читает артефакт своим Read); ЧК — по пути в промпте. Системка для АГ — в параметр `system`/`system_file`. Собрать ответы всех участвующих богов.

## Что даём каждому богу (идентично всем богам прогона)

**Системка** (для Codex — в начале `prompt`; для АГ — в параметр `system`; для ЧК — в `--append-system-prompt`): **ядро v2** (божественный промпт из `~/.claude/CLAUDE.md`, блок-цитата) **+ ТБ-надстройка ниже, дословно**. Отдельный read-only-блок не нужен — запреты вшиты в надстройку. **Fallback:** если ядра v2 в `~/.claude/CLAUDE.md` нет (блок из `CLAUDE.md.template` не установлен) — взять fallback-промпт из skill `takt` (шаг 3, «Промпт для оценщиков») + ТБ-надстройку.

### ТБ-надстройка (дословный текст, единый источник правды)

```
=== РЕЖИМ ТБ: НЕЗАВИСИМЫЙ АУДИТ ===

Ты — независимый аудитор и последняя линия обороны перед попаданием этого кода в основную ветку. Автора рядом нет, защищать код некому: артефакт — единственный источник правды о том, что код ДОЛЖЕН делать. Расхождение кода с интентом — это находка, даже если код «красивый». Репозиторий доступен тебе на чтение из текущей директории.

КАК РАБОТАТЬ:
1. Прочитай артефакт целиком: интент, diff, формат findings, историю прошлых раундов (если есть — решённое повторно не поднимай).
2. Не ограничивайся строками diff'а: открой изменённые файлы целиком, проследи вызовы изменённых функций (кто вызывает — что вызывается), посмотри связанные тесты. Баг чаще живёт на стыке diff'а с нетронутым кодом.
3. Пройди по классам багов: логика и границы (off-by-one, пустые входы, null); обработка ошибок (проглоченные исключения, кривой recovery); ресурсы (утечки, незакрытые хендлы/транзакции); конкурентность и повторный запуск (гонки, идемпотентность); данные (кодировки, пути Windows/POSIX, таймзоны, форматы); security (инъекции, секреты в коде, валидация на границах); контракты (сломанные сигнатуры/API/форматы для существующих вызовов); производительность на реалистичных объёмах; соответствие интенту (сделано ВСЁ заявленное? нет лишнего?).

ЧТО РЕПОРТИТЬ:
- Репорть ВСЁ найденное, включая находки с низкой уверенностью и низкой severity, — НЕ фильтруй сам «по важности». Ниже по конвейеру арбитр проверяет каждую находку по коду и отсеивает ложное; твоя метрика — ПОКРЫТИЕ. Лучше находка, которую отсеют, чем молча пропущенный баг.
- Каждая находка обязана опираться на конкретный код: файл:строка + сценарий отказа (вход → шаг → неверный эффект). Находка «по ощущениям», без опоры на код — запрещена. НЕ выдумывай баги ради количества: «чисто» — валидный и уважаемый результат.
- НЕ репорть: стиль, нейминг, «добавьте комментарии», вкусовые рефакторинги — если за ними не прячется реальный баг.
- Баг в коде, не тронутом diff'ом, — в отдельную секцию «ВНЕ SCOPE», не смешивай с findings по diff'у.
- Формат находок — строго из артефакта. Последняя строка ответа: `ВЕРДИКТ: N findings (X blocker / Y major / Z minor / W nit)` либо `ВЕРДИКТ: чисто`.

ЗАПРЕТЫ (всегда, без исключений):
Ты аналитик, НЕ исполнитель. НИ В КОЕМ СЛУЧАЕ НЕ МЕНЯЙ КОД И ФАЙЛЫ. ТОЛЬКО АНАЛИЗ. Запрещено: править/создавать/удалять файлы; запускать код, тесты и любые изменяющие команды; git-команды кроме read-only (status/log/show/diff); ставить/удалять пакеты; трогать конфиги, БД, инфраструктуру. Фиксы предлагай словами внутри findings — применяет их только арбитр (основной процесс) после верификации.
```

**Почему coverage-first, а не «репорть только важное»:** все боги — сильные современные модели, которые исполняют инструкции буквально: фильтр «только критику» они выполняют честно и молча роняют recall (находят баг → сами решают, что он «недостаточно важен» → не репортят). Официальная рекомендация Anthropic для review-харнессов с downstream-верификатором: искатели дают покрытие + severity + уверенность, фильтрует арбитр. У ТБ арбитр есть — это основной процесс.

**Артефакт — ОДИН файл** (`<repo>/.tb-artifact.md`, временный, не коммитить), всем богам даём путь к нему. Один файл = буквально одинаковый вход у всех, без argv-лимита Windows и тихой обрезки. Внутри:
1. **Что код должен делать + инварианты** — коротко, из ТЗ/тестов если есть (внешний источник надёжнее, чем из головы автора — иначе кривой инвариант заразит всех троих одинаково). Формулировать как **проверяемые критерии** («выдерживает пустой список», «старый API не ломается»), а не общие слова. БЕЗ «почему я так сделал».
2. **Изменения** — кумулятивный diff `git diff <base>..HEAD` (вся серия такта от базового коммита, НЕ одиночный fix-коммит — иначе боги ревьюят заплатку в вакууме и пропускают, что фикс сломал в фиче).
3. **Формат findings**: `[severity] файл:строка — категория — проблема + сценарий отказа (вход → шаг → эффект) — фикс словами — уверенность(0..1)`; severity ∈ {blocker, major, minor, nit}; категория — одно слово (логика/ошибки/ресурсы/конкурентность/данные/security/контракт/perf/тесты/интент — облегчает дедуп арбитру). В конце ответа — строка `ВЕРДИКТ: …` или `ВЕРДИКТ: чисто`; замечания по нетронутому коду — секция «ВНЕ SCOPE».
4. **История прошлых раундов** (только раунд 2+): что принято / что отклонено и почему — чтобы боги не поднимали заново решённое.

**Один `<base>` на весь такт.** Зафиксировать базовый SHA один раз; diff всегда от него — иначе боги прочитают разные версии.

## Read-only

- Запреты (не менять файлы, не запускать код/тесты, git только read-only) — вшиты в блок «ЗАПРЕТЫ» ТБ-надстройки, отдельно ничего слать не нужно.
- **ЧК** — вдобавок технически: `--disallowedTools "Edit Write NotebookEdit"` (физически не пишет).
- **Codex / АГ** — барьер только на инструкции (Codex с `danger-full-access`, agy с v1.3.0 видит проект); за месяцы Codex не нарушал.
- Запуск кода/тестов запрещён всем богам: выполняет всё основной процесс и при нужде отдаёт богам результат на анализ.
- Код меняет **только основной процесс** после арбитража.

## Арбитраж (основной процесс)

Цель — **НЕ ПРОПУСТИТЬ баг** (чтобы через время не вылез). Перестраховка, а не экономия фиксов.

- Собрать findings всех богов прогона. Одно и то же от нескольких → почти точно реально.
- Каждое проверить по коду. **Сомневаешься — считаешь баг реальным.**
- Отклонять замечание **только с доказательством из кода/ТЗ**. НИКОГДА не отклонять по «я так задумал» — спорный инвариант вернуть богу на проверку, явно его сформулировав.
- Фиксить валидное минимальным изменением.

## Цикл (когда ревьюим код)

1. Зафиксировать базовый SHA (состояние до такта). `git commit` локально, **без push**.
2. Собрать артефакт-файл (кумулятивный diff от базы + интент + формат). Три бога параллельно на него.
3. Арбитраж → отдельный fix-коммит.
4. Обновить артефакт-файл (новый кумулятивный diff + история раунда), повторить, пока боги не дадут **0 blocker/major**. Максимум 3 раунда → стоп, спросить юзера. **Стоп-патчить точечно:** одно и то же замечание пережило 2 раунда фиксов → третью заплатку не клеить, пересмотреть подход (возможно, кривой инвариант или неудачная декомпозиция) и/или эскалировать юзеру.
5. Push проверенного (если push разрешён). Удалить артефакт-файл.

## Если бог упал / молчит

2 ретрая. Не вышло → **ТБ неполный, сказать юзеру** (ждать / частичный ТБ / выйти). НЕ заменять упавшего бога самим основным процессом — это вернёт author-bias.

## Когда активировать

«Вызови ТБ» / «ТБ» / «Триумвират», и автоматически внутри ТАКТ (skill `takt`) как ревью коммита. НЕ на обычные вопросы — ресурсоёмко.
