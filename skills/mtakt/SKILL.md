# МТАКТ — Микро-ТАКТ

Один такт системы ТАКТ как самостоятельный законченный цикл: **вся задача = один такт**, без декомпозиции и без плана на подтверждение. Автоматизирует ручной флоу юзера: «реализуй всё → коммит+пуш → ТБ (без ЧК) → если что пофикси → снова коммит+пуш».

Механика богов, артефакта и арбитража — по skill `tb` (единый источник правды). Git-дисциплина и запреты — из skill `takt`. Здесь — только дельты и порядок.

## Дефолты (отличия от полного ТАКТ)

| Что | ТАКТ | МТАКТ |
|---|---|---|
| Декомпозиция + план на подтверждение | да | **нет** — озвучил в 1-2 строки, что делаю, и делаю |
| Состав ТБ | Codex + АГ (+ЧК только по явному слову юзера) | **Codex + АГ; ЧК — тоже только по явному слову** |
| Push | только после закрытия ТБ | **сразу после коммита реализации** (осознанное отличие); ТБ-фиксы — коммитом сверху |
| Раунды ревью | до 0 blocker/major, макс 3 | **1 раунд**; авто-раунд 2 только если применён фикс blocker-уровня |
| Ветка | спросить про feature-ветку | текущая ветка как есть |

**Модификаторы** (слова в запросе юзера):
- «с чк» / «полный ТБ» → подключить ЧК третьим богом (`--effort high`)
- «чк-макс» → подключить ЧК с `--effort max`
- «без пуша» → только локальные коммиты, push не делать
- «строгий» → push отложить до полного закрытия ТБ (как в ТАКТ/tb)

## Алгоритм

### 0. Мини-preflight (без вопросов юзеру в happy path)
- `git rev-parse --is-inside-work-tree` — не репо → стоп, спросить.
- Зафиксировать **base SHA** = текущий HEAD (от него кумулятивный diff артефакта на все раунды). Нет HEAD → initial-commit mode, артефакт = staged diff.
- `git status --short --branch`. Dirty tree: чужие правки **пересекаются** с файлами задачи → стоп, спросить (иначе закоммичу чужое); не пересекаются → игнорировать, `git add` только своих файлов (никогда `-A`).
- Detached HEAD → спросить. Иначе — работаем на текущей ветке, feature-ветку не создаём.
- Upstream есть → push по умолчанию разрешён; нет → спросить один раз перед `git push -u`.

### 1. Реализация
- Вся задача целиком, минимальный diff, строго в границах задачи. Попутные находки (опечатки, чужие баги) — в отчёт, не править, если не блокируют сам фикс.
- Bugfix → сначала назвать корневую причину (симптом → где ломается → почему старое поведение неверно), не лечить симптом вслепую; причина быстро не находится → стоп, предложить полный ТАКТ.
- Задача меняет поведение и оно тестируемо → тест красным→зелёным: убедиться, что тест ПАДАЕТ на старом коде (зелёный сразу = пустышка), потом чинить. Мелочь/конфиг/доки — не форсить, отметить в отчёте.
- Прогнать тесты/линт, если есть и неинтерактивны.

### 2. Коммит + пуш
- Просмотреть diff перед staging: только изменения задачи; нет секретов (ключи, токены, `.env` с реальными значениями); нет чужих правок. Подозрение → стоп, спросить.
- `git add <файлы задачи>` → коммит с короткой строкой «что сделано» → push (если разрешён).
- Pre-commit упал → чинить причину, НЕ `--no-verify`. Non-fast-forward → стоп, спросить, без auto-pull/rebase.

### 3. ТБ-лайт (по skill `tb`)
- Артефакт `<repo>/.tb-artifact.md` (временный, не коммитить): интент «что код должен делать» + кумулятивный `git diff <base>..HEAD` + формат findings `[severity] файл:строка — проблема — фикс — уверенность`. **БЕЗ своих рассуждений «почему я так сделал»** — заражают blind-review. Шум исключить (lock-files, `*.min.*`, dist, generated).
- Боги: **Codex + АГ параллельно в одном tool-use блоке**. Системка = ядро v2 (божественный промпт из CLAUDE.md) + ТБ-надстройка из skill `tb` (coverage-first и read-only внутри). Точные параметры вызовов — skill `tb`.
- Своё мнение о коде НЕ формировать до сбора ответов богов (анти-author-bias).
- Бог упал → 2 ретрая → продолжить с одним оставшимся + жирная пометка «ТБ неполный» в отчёте. Авто-замену на ЧК НЕ делать (ЧК — только по явному слову юзера); можно ПРЕДЛОЖИТЬ юзеру подключить ЧК на этот прогон. Собой упавшего бога не заменять никогда.

### 4. Арбитраж (правила — skill `tb`)
- Дедуп: оба бога нашли одно → high-priority. Каждое замечание проверить по коду.
- **Сомневаешься → баг реален.** Отклонять только с доказательством из кода/ТЗ, никогда по «я так задумал».
- Несовместимые фиксы → выбрать один с обоснованием сам (микро-режим, юзера не дёргать), решение зафиксировать в отчёте.
- Замечание вне границ задачи → в отчёт как рекомендация, не фиксить (если не блокирующий баг самого фикса).

### 5. Фиксы
- Валидные → минимальный diff в границах задачи (фикс закрывает класс проблемы, не единичный вход) → коммит `ТБ-фикс: <что>` → push.
- Применён фикс **blocker**-уровня → авто-раунд 2: обновить артефакт (свежий кумулятивный diff от base + история раунда: принято/отклонено и почему), повторить шаги 3-4. После раунда 2 — стоп в любом случае, дальше только по команде «повтори ревью».
- Валидных замечаний нет → фикс-коммита нет, так и сказать.

### 6. Завершение
- **Свежее доказательство:** после всех фиксов — прогон тестов/линта в ЭТОМ цикле; в отчёт — фактический результат (passed/failed), а не «должно работать». Режим «без пуша» прогон не отменяет; тестов нет → честно так и написать.
- Удалить `.tb-artifact.md`.
- Отчёт юзеру одним блоком: что сделано; хеши коммитов; push status; ТБ-сводка (кто отвечал / findings всего / валидных / принятых); отклонённые одной строкой с причиной; замены богов, rule-breaks, попутные находки.

## Жёсткие правила (наследуются из ТАКТ)

- ЗАПРЕТ на `--no-verify`, `commit --amend`, rebase/squash, force-push, auto-pull — без явной команды юзера на конкретное действие.
- ЗАПРЕТ на коммит секретов и чужих стартовых изменений.
- ЗАПРЕТ на правки вне границ задачи («заодно поправил» не бывает).
- ЗАПРЕТ на пропуск ТБ — без ревью это не МТАКТ, а обычный режим; на то юзер и позвал МТАКТ.
- Diff реализации > ~1500 осмысленных строк → это уже не «микро»: стоп, предложить полный ТАКТ (или chunked review по skill `tb`, если юзер настоит).

## Команды режима

- «повтори ревью» — ещё раунд ТБ на текущий кумулятивный diff.
- «выйти из мтакт» — закрыть режим без reset'ов и удаления изменений.

## Edge cases

- ТБ нашёл критику в уже запушенном коммите → фикс-коммит сверху немедленно; не amend, не force-push.
- Push отклонён сервером (protected branch, auth) → стоп, эскалация юзеру.
- Diff не помещается в контекст богов → chunked: file-level summary + полный diff ключевых файлов; список changed files не терять.
- Юзер посреди цикла меняет задачу («переделай иначе») → стоп, пересогласовать, скоупы не смешивать.
- Задача по ходу оказалась многоэтапной → стоп, предложить полный ТАКТ с декомпозицией.
